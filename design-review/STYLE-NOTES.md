# Design review: shared styles and accessibility

Scope: the review's contrast, focus, responsive information, mobile sorting and component-consistency fixes. Existing green identity and plain HTML/CSS technology are retained. No browser, server, screenshot or assistive-technology workaround was used.

## Files changed

- `docs/design-review.css`: final shared override layer, loaded after legacy inline rules by the integrating agent. It defines the shared palette, typography, spacing and component aliases once; `html[data-theme="dark"]` changes only semantic color tokens. Main planner/register styles now consume those tokens.
- `docs/project-plan.css`: visible `.pp-mobile-dates` text equivalent at 768px and below, with compact responsive work rows. The project-plan JS supplies the actual dates/status text.
- `docs/meeting-workspace.css`: action and attendee sort headers remain available as wrapping controls in mobile card layouts.
- `design-review/tests/style-audit.cjs`: source and numerical contrast checks.

## Behavior and design changes

- Muted text now uses `--ui-muted`, including timeline labels and project facts. Semantic badge colors and primary button text have separate light/dark tokens.
- Focus outlines use a contrast-tested color throughout; the dark sidebar gets a separate light outline. Input boundaries have a contrast-tested token rather than the previous near-white line.
- My day becomes one column at 1100px, before the sidebar reduces available room below the old grid minimum. Navigation reflows at 900px.
- Projects, clients, opportunities, portfolio and meeting registers become labelled cards at 1240px and below. Header controls remain visible for sorting. The integrating JS adds each cell's `data-label`.
- Timeline tasks retain their date range and status when chart tracks are hidden. Mobile work item controls remain adjacent to their item, with long text allowed to wrap where needed.
- Coarse-pointer controls use a 44px minimum target. The single date calendar expands into a viewport-bounded popup so seven 44px day targets can fit even at 320px. Actual target overlap still needs rendered verification.
- Existing cards, forms, badges, buttons, filters and modal surfaces share the final token layer. Font sizes are normalized for key headings, compact body text and metadata, without changing information architecture.
- Light/dark mode uses `html[data-theme="dark"]`; the integrating agent owns the preference control and state.

## Limitations and remaining verification

- No rendered check at 1440px, 768px, 375px or 320px; no screenshot, keyboard traversal, screen-reader, axe or Lighthouse run. The browser restriction remains in effect.
- Existing module and inline legacy rules remain in the code. The final layer unifies active styles without a risky unrelated rewrite. A later cleanup can replace superseded declarations after visual regression testing.
- Main mobile cards depend on the JS-provided `data-label`; timeline text depends on the `.pp-mobile-dates` element. These are integration responsibilities, not generated by CSS.
- Sticky table headings are declared consistently. Browser behavior within the existing scroll containers must still be checked with a realistically long dataset.
- No claim of WCAG conformance: real layout, focus visibility, zoom, keyboard paths and assistive technology require verification. The requested 44px coarse target exceeds the WCAG 2.2 AA 24px target minimum; no unrendered target-spacing conformance claim is made.
